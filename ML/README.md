# ML — data cleaning, feature engineering, and grounding the 3D lab

Two pipelines live here, both documented end to end and re-runnable from scratch.

## 1. `feature_engineering.ipynb` — findings.csv cleaning + feature engineering

```bash
python3 build_notebook.py
jupyter nbconvert --to notebook --execute --inplace feature_engineering.ipynb
```

(`build_notebook.py` is the source of truth — it writes the `.ipynb`. Edit that, not the
notebook JSON directly, then re-run both commands.)

**Input**: `../findings/findings.csv` — 111 curated NASA PSI/NTRS findings, already mapped
onto Flamme's ten standard conditions.

**Outputs** (generated, not hand-edited):
- `findings_clean.csv` — cleaned findings (108 rows; 3 "Evidence gap" rows split out),
  typed numeric columns, explicit `*_missing` flags, parsed gravity regime.
- `findings_gaps.csv` — the 3 evidence-gap rows (untested-condition notes), kept separate
  since they carry no measurement.
- `findings_features.csv` — `findings_clean.csv` plus engineered columns (midpoints,
  one-hot/ordinal/frequency encodings, log1p of sample size).
- `feature_dictionary.md` — auto-generated column-by-column description of
  `findings_features.csv`, regenerated by the notebook so it can't drift out of sync.

Scope: this covers the 111-row curated findings table only. The 3,000+-row raw PSI test
matrices in `../flame_in_freefall_data/cleaned/cleaned_values.csv` are the bigger pipeline
below.

## 2. `build_flex_model.py` — grounding the 3D lab in real NASA data (plan item 4)

```bash
python3 build_flex_model.py
```

Pivots, cleans, and feature-engineers the 273 individual FLEX (PSI-69) droplet-flame test
rows out of `../flame_in_freefall_data/cleaned/cleaned_values.csv` (long/tidy, 22 raw PSI
tables), then fits two real models with held-out test metrics:
- Logistic regression → self-extinguish probability (test AUC 0.895, n=222)
- Linear regression → burning-rate constant K (test R² 0.582, n=257)

**Outputs**:
- `flex_tests_clean.csv`, `flex_feature_dictionary.md` — the cleaned per-test table and its
  column reference.
- `../src/flexModel.json` — scaler + coefficients + the 273 real tests themselves (for
  nearest-neighbor lookup and citation), consumed client-side by `../src/flexModel.js`
  (`predictFlex`, `nearestFlexTest`, `inTrainingRange`). No backend, no training in the
  browser — just the already-fitted numbers.

**Where it shows up**: `/lab` → "Grounded in NASA FLEX data" card — predicted self-extinguish
probability + burning rate for the current O₂/pressure slider values, the single closest
real FLEX test with its actual measured outcome and a link to its NASA PSI source, and an
explicit refusal to predict (never extrapolate silently) when the sliders sit outside the
tested envelope (O₂ 12–34%, pressure 0.69–2.73 atm).

**Data-quality note caught by this pipeline**: one FLEX row had a literal `0 mmHg` ambient
pressure reading — physically impossible for a sealed test chamber. Treated as missing, not
a valid near-vacuum test; fixing it improved the burning-rate model's R² from 0.45 to 0.58.

**Scope, stated honestly in the UI and here**: FLEX is free-floating liquid-droplet
combustion (methanol/heptane) — a different physical regime from the lab's solid-sample
sheet (SIBAL/PMMA/silicone, `../src/labModel.js`). This is why it is wired in as a
clearly-labeled side-by-side comparison, not blended into the illustrative solid-sample
curves: that would misrepresent the physics. Grounding the solid-sample model itself needs
BASS/BASS-II/Saffire row-level data (same cleaning approach, different source table) — a
natural next step, not done here.

## 3. `build_cfig_model.py` — second trained model: CFI-G hot ignition (PSI-159)

```bash
python3 build_cfig_model.py     # numpy + pandas only (no sklearn needed)
```

Logistic regression on **325 CFI-G tests** from PSI-159: 179 *normal-flame* tests (O₂ 18–40 %) plus 146
*inverse-flame* tests (oxidiser fed from the burner, O₂ 12–85 % — the highest-oxygen microgravity
tests in PSI). Question: did the gaseous-fuel flame hot-ignite, from O₂ %, pressure (bar), fuel
family (propane / ethane / butane) and flame configuration. Eight inverse rows marked "flash"
are ambiguous and excluded.

Honest results (seeded 75/25 split, n_test=82): held-out AUC 0.83, 5-fold CV AUC 0.81 (min 0.74),
but accuracy 0.805 against 0.809 for always guessing "ignites" — the model ranks flames better than
chance without beating the majority guess on accuracy, because hot ignition is the common outcome
(74 % of normal, 90 % of inverse tests). Per type, held-out AUC is 0.76 (normal) and 0.97 (inverse).
Before the inverse table was added, the normal-flame-only model had AUC 0.73 on 45 held-out tests.
Inverse-flame "O₂" is the oxidiser-stream concentration, not the ambient atmosphere, so the flame
configuration is an explicit input and each is only predicted inside its own tested range
(normal 18–40 % O₂ and 0.51–3.04 bar; inverse 12–85 % O₂ and 0.50–3.31 bar); outside it the
model returns null. Output `../src/cfigModel.json`, consumed by `../src/cfigModel.js`, shown on `/lab`
under the FLEX card with a Normal / Inverse toggle. Not a solid-material model, and fuel dilution
(e.g. "30% butane") is not modelled.
Not extended: BASS / BASS-II / SLICE / SAFFIRE tables are test logs without an outcome column.
